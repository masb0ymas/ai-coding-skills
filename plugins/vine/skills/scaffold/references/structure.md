# vine app structure

Paths are relative to the **source root**: the app root for vinext, `src/` for
vite. `@/` maps to the source root in both.

## Layout

```
app/ (vinext) | routes/ (vite)   pages; thin: render one block component, guard the session
components/
  ui/                shadcn/ui primitives (components.json); data-grid*, sidebar, field, ...
  block/common/      app-wide composites: react-table, section-card, empty-state, dialogs, cell-item
  block/form/        TanStack Form field components, registered in hooks/form.tsx
  block/<group>/<resource>/  feature UI: table.tsx, column.tsx, form.tsx
  layout/sidebar/    shell: app-sidebar, nav-main, nav-user, layout
config/env.ts        the only place env is read (t3 env + zod)
data/sidebar-menu.ts menu per role (MENUS) — only routes that exist
hooks/               form hook (useAppForm), use-pagination-query, use-debounce, use-mobile
lib/
  api/
    models/          response types; `Models` namespace in index.ts
    dtos/            zod request schemas (+ paginate, parse.ts → parseDto)
    services/        axios calls per resource via clientResource(); registry in index.ts
    services/types/  declared HTTP methods per service
    queries/         queryOptions/mutationOptions per resource; registry in index.ts
    client-fetch.ts  the one axios instance: Bearer token, 401 → refresh once → /sign-in
    resource.ts      clientResource(path, methods) → list/get/store/update/edit/delete
    axios-error.ts   axiosErrorMessage / toastAxiosError (reads the API envelope)
  auth/              token-storage (cookies), email-auth (sign in/out), handler (session guards)
  providers/         react-query (getQueryClient), decoration (theme + nuqs adapter), themes
  constants/         ROLES, AUTH_STORAGE_KEYS, DEFAULT_PAGINATE
  validation.ts      zod helpers with uniform messages: requiredString, optionalString, ...
types/               api.ts (envelope, HTTP_METHOD, ResourceMethods), column, form, menu, select, time
```

## Data flow

`page/route → components/block/<x>/table.tsx → useQuery(queries.x.list(params))
→ services.x.list → api (axios) → backend /api/v1/x`

Writes: `form.tsx → useMutation(queries.x.create()) → parseDto(schema, value)
→ services.x.store` and `onSuccess` invalidates `[X_QUERY_KEY]`.

## Backend contract

- Base path `/api/v1`. Dev proxies `/api` to `http://localhost:8080`
  (vinext: `next.config.ts` rewrites + `API_PROXY_TARGET`; vite: `vite.config.ts`
  proxy + `VITE_API_PROXY_TARGET`). A cross-origin API sets `NEXT_PUBLIC_API_URL` / `VITE_API_URL`.
- Responses: `{ data, metadata: { total, offset, limit }, message }`
  (`types/api.ts`). Lists take `offset` (0-based), `limit` (≤ 100), optional `search`.
- Errors: `{ message, errors?: [{ code, field, message, param }] }`.
- Auth at `/api/v1/auth`: `sign-in`, `refresh`, `me`, `sign-out`; tokens
  (`access_token`, `refresh_token`, `id_token`, `expires_in`) stored as
  non-httpOnly cookies and sent as `Authorization: Bearer`.

## vinext vs vite — the only differences

| Concern | vinext (`vinext-cf`, `vinext-docker`) | vite (`vite`) |
|---|---|---|
| Source root | app root | `src/` |
| Page file | `app/(app)/<path>/page.tsx` (default export) | `src/routes/(app)/<path>/index.tsx` with `createFileRoute('/(app)/<path>/')` |
| Layout / guard | `app/(app)/layout.tsx`: `await requireSession()` (cookie presence, server side) | `routes/(app)/route.tsx`: `beforeLoad: requireSession` (fetches profile, client side) |
| Client code | `'use client'` at top of any component using hooks/events | no directive |
| Links / navigation | `next/link` `href`, `next/navigation` `useRouter`, `usePathname`, `redirect` | `@tanstack/react-router` `Link to`, `useNavigate`/`useRouter`, `useLocation`, `throw redirect({ to })` |
| URL state adapter | `nuqs/adapters/next/app` | `nuqs/adapters/tanstack-router` |
| Env | `NEXT_PUBLIC_*` via `process.env.NAME` listed in `runtimeEnv` | `VITE_*` via `import.meta.env` |
| Dev flag | `process.env.NODE_ENV === 'development'` | `import.meta.env.DEV` |
| Error / 404 | `app/error.tsx`, `app/not-found.tsx` | `errorComponent` / `notFoundComponent` in `routes/__root.tsx` |
| Route tree | file system, nothing generated | `src/routeTree.gen.ts`, regenerated by the Vite plugin or `pnpm generate-routes` (commit it) |
| Cloudflare only | `cloudflare.config.ts` (Worker name, bindings, assets), `@cloudflare/vite-plugin` in `vite.config.ts`, `pnpm run deploy` | — |
| Docker only | `output: 'standalone'` in `next.config.ts` → `dist/standalone/server.js` | `dist/` static files |

Everything under `lib/api` (except the env name in `client-fetch.ts`'s
`baseURL`), `components/ui`, `types`, and the shape of `components/block` is
identical across variants — code moves between them by applying only the rows above.

## Starter features

- Email/password sign-in, token refresh with a single in-flight refresh, sign-out.
- Sidebar shell with role-based menus (`ROLES.ADMIN`, `MENTOR`, `USER`).
- Dashboard with an API health card.
- `master/organization`: the reference CRUD module (search, pagination in the
  URL via nuqs, create/edit dialog, delete confirm).
- Light/dark theme (next-themes), sonner toasts, TanStack devtools in dev.
